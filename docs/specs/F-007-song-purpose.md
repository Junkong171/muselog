# F-007: 연습곡 목적과 파트 저장

- 상태: 구현됨 (수정 1차: 파트(세부 전공) 선택 추가, 카드 버튼을 "편집" 하나로 합침)
- 작성일: 2026-10-30
- 관련 파일: `src/App.jsx` (곡 추가 `addSong`, 곡 추가 폼, 연습곡 카드 목록 `song-list`), `src/lib/songs.js`, `src/lib/songs.test.js`, `src/App.css`, `CLAUDE.md` (localStorage 키 표)

## 목적

같은 곡이라도 왜 연습하는지(공연, 축가, 레슨 과제 등)를 적어 두면 연습할 때 무엇에 집중할지 떠올리기 쉽다. 곡을 추가할 때 목적을 함께 적고, 연습곡 카드에서 늘 보이게 한다. 이미 저장한 곡에도 나중에 목적을 넣거나 고칠 수 있게 한다. 또 지금은 새 곡이 모두 "보컬"로 저장되는데, 보컬·기타·피아노·베이스·드럼·작곡 같은 파트(세부 전공)를 곡마다 고를 수 있게 한다.

## 사용자 시나리오

1. 사용자가 "+ 곡 추가하기"를 누르고 제목 "축하합니다", 아티스트, 파트 "피아노", 목적 "친구 결혼식 축가"를 입력해 저장한다.
2. 연습곡 카드에 "아티스트 · 피아노"가 보이고, 그 아래로 "목적 · 친구 결혼식 축가"가 보인다.
3. 예전에 저장한 "밤편지" 카드에서 "편집"을 눌러 파트를 "기타"로 바꾸고 목적에 "12월 공연"을 입력하고 Enter를 누르면 그 카드에 바로 반영된다.
4. 공연이 끝나 목적을 바꾸고 싶으면 다시 "편집"을 눌러 고친다. 목적을 비우고 저장하면 목적이 사라진다.

## 수용 기준

### 곡 추가할 때

- [ ] AC-1: "+ 곡 추가하기" 폼에 제목, 아티스트 다음으로 "목적 (선택)" 입력 칸이 있다. 비워 두어도 곡은 저장된다.
- [ ] AC-2: 목적 칸에 글자를 넣기 시작하거나 칸을 누르면 예시 목록(공연, 축가, 레슨 과제, 오디션, 취미)이 제안으로 뜨고, 골라도 되고 직접 써도 된다. 목적은 최대 30자까지 입력된다.
- [ ] AC-3: 저장하면 목적은 앞뒤 공백을 빼고 곡과 함께 저장되며, 폼의 목적 칸도 제목·아티스트 칸처럼 비워진다.
- [ ] AC-3a: 폼의 아티스트 다음에 "파트" 선택이 있고, 보컬 / 기타 / 피아노 / 베이스 / 드럼 / 작곡 / 그 외 중 하나를 고른다. 기본값은 보컬이다. 저장하면 고른 파트가 곡과 함께 저장되고, 저장 후 선택은 다시 보컬로 돌아간다.

### 카드 표시

- [ ] AC-4: 카드의 "아티스트 · 파트" 줄에는 그 곡에 저장된 파트가 보인다. 목적이 있는 곡은 그 줄 아래에 "목적 · (목적 내용)"이 눈에 띄는 작은 표시(배지)로 보인다. 목적이 없는 곡은 이 표시가 없다.
- [ ] AC-5: 목적 표시는 대시보드의 연습곡 목록과 "내 연습곡" 탭 둘 다에서 같게 보인다. 정렬 기준을 바꿔도 각 곡의 목적이 그 곡을 따라간다.

### 넣기와 고치기

- [ ] AC-6: 모든 카드에 "편집" 글자 버튼이 있다. 누르면 그 자리에 파트 선택과 목적 입력 칸이 열리고(지금 파트와 목적이 미리 채워짐) 목적 칸에 바로 입력할 수 있다. 한 번에 한 카드만 열린다.
- [ ] AC-7: 목적 칸에서 Enter를 누르거나 "저장"을 누르면 파트와 목적이 함께 바뀌어 저장된다. 목적을 비운 채 저장하면 목적이 지워진다. Esc를 누르거나 "취소"를 누르면 아무것도 바뀌지 않고 닫힌다.
- [ ] AC-8: 파트나 목적을 고쳐도 그 곡의 제목, 아티스트, 진행률, 순서는 바뀌지 않고, 다른 곡에는 영향이 없다. "진도 +10%"도 그대로 동작한다.

### 저장과 기존 데이터

- [ ] AC-9: 목적은 `muselog-songs`의 각 곡에 `purpose` 항목(문자열)으로, 파트는 기존 `type` 항목에 저장되어 새로고침해도 유지된다.
- [ ] AC-10 (마이그레이션): `purpose`가 없는 기존 곡은 목적 없음(`""`)으로 읽고, 나머지 항목(id, title, artist, progress)은 그대로 둔다. `purpose`가 문자열이 아니면 목적 없음, 30자보다 길면 30자까지로 읽는다. 이 처리는 `normalizeSongs` 함수(`src/lib/songs.js`)로 하고 앱이 멈추지 않는다.
- [ ] AC-10a (마이그레이션): 기존 곡의 `type`이 파트 목록에 있는 값(예: 예전 기본 곡의 "보컬", "기타")이면 그대로 둔다. `type`이 없거나 문자열이 아니거나 빈 값이면 "보컬"로, 목록에 없는 다른 문자열이면 "그 외"로 읽는다. 이것도 `normalizeSongs`가 처리한다.
- [ ] AC-11: 연습 기록 탭의 곡 선택, 연습 통계의 곡별 시간, 작업실 메트로놈의 곡 선택은 이전과 똑같이 동작한다.

### 공통

- [ ] AC-12: `normalizeSongs` 테스트를 `src/lib/songs.test.js`에 추가한다. (목적 없음, 문자열 아님, 30자 초과, 다른 항목 보존, 원본을 바꾸지 않음, 파트 그대로 / 없음 → 보컬 / 모르는 값 → 그 외)
- [ ] AC-13: 대시보드, 연습 기록, 연습 통계, 캘린더, 작업실이 이전과 똑같이 보이고 동작한다.
- [ ] AC-14: `npm test`, `npm run build`, `npm run lint`가 오류 없이 끝난다. (lint 경고는 기존 개수보다 늘지 않는다)

## 비범위

- 목적으로 거르기·정렬하기 (예: "축가만 보기")
- 목적마다 마감일이나 D-DAY 연결 (캘린더 연결)

- 예시 목록을 사용자가 바꾸기
- 연습 기록이나 통계에 목적 표시
- 파트로 거르기·정렬하기, 파트별 통계
- 파트 목록을 사용자가 바꾸거나 한 곡에 파트 여러 개 고르기

## 확인 방법

- 자동: `npm test`, `npm run build`, `npm run lint`
- 수동 (브라우저):
  1. `npm run dev` 실행 후 http://localhost:5173/ 열기
  2. 예전 곡 3개가 그대로 있고(파트 보컬·기타·보컬) 목적 표시가 없는지, "편집" 버튼이 보이는지 본다.
  3. "+ 곡 추가하기"에서 파트를 "피아노"로 고르고, 목적 칸을 눌러 예시 목록이 뜨는지 보고, 목적을 넣어 곡을 저장해 카드에 "· 피아노"와 "목적 · …"이 보이는지 본다.
  4. 예전 곡에서 "편집" → 파트 바꾸기 + 목적 입력 → Enter로 둘 다 저장되는지, 다시 "편집"에서 Esc로 취소되는지, 목적을 비우고 저장하면 사라지는지 본다.
  5. 정렬을 바꿔도 목적이 곡을 따라가는지, 새로고침해도 남는지 본다.
  6. "내 연습곡" 탭에서도 같게 보이는지, 연습 기록·통계·작업실이 그대로인지 본다.
