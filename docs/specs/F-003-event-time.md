# F-003: 캘린더 일정 시간 선택

- 상태: 구현됨 (수정 4차: [시] : [분] 두 칸 입력 + 칸별 선택 목록)
- 작성일: 2026-10-25
- 관련 파일: `src/App.jsx` (일정 입력 상태 51줄, addEvent 125–135줄, 일정 계산 175–177줄, 캘린더 화면 459–525줄, 대시보드 카드 537–542줄), `src/lib/calendar.js` (normalizeEvents 44줄, upcomingEvents 52줄), `src/lib/calendar.test.js`, `src/App.css`

## 목적

일정을 추가할 때 시간(예: 오후 2시 레슨)을 함께 적어 두어, 날짜뿐 아니라 몇 시 일정인지도 바로 본다. 시간은 선택 사항이라 기존처럼 날짜만 있는 일정(종일 일정)도 그대로 쓸 수 있다.

## 사용자 시나리오

1. 사용자가 캘린더에서 날짜를 고르고 제목을 입력한다.
2. 시간 입력칸에서 "14:00"을 고르고 저장한다. (시간을 비워 두면 종일 일정)
3. 일정 목록, 다가오는 일정, 대시보드 카드에 "14:00"이 함께 보인다.

## 수용 기준

- [ ] AC-1: 캘린더의 일정 입력 영역에 제목, 메모와 함께 시간 입력이 `[ 시 ] : [ 분 ]` 모양으로 보인다. 네모 칸 2개(시, 분) 사이에 ":"가 항상 표시되어 있고, 빈 칸에는 각각 "시", "분"이 흐리게 보인다. 두 칸이 모두 비어 있으면 종일이다.
- [ ] AC-1a: 두 칸 모두 숫자만 들어가고(최대 2자리), 누르면 바로 직접 입력할 수 있다. 시 칸에 2자리를 치면 분 칸으로 자동으로 넘어간다.
- [ ] AC-1b: 시 칸을 누르면 칸 아래에 "종일", "00"~"23" 목록이, 분 칸을 누르면 "00", "05", …, "55"(5분 단위) 목록이 열린다. 목록에서 누르면 그 값이 칸에 들어가고 목록이 닫힌다. 시 목록의 "종일"을 누르면 시·분 칸이 모두 비워진다. 칸 밖을 누르거나 Esc를 누르면 목록이 닫힌다.
- [ ] AC-1c: 칸에 숫자를 치면 목록이 그 숫자로 시작하는 값만 남긴다. (예: 시 칸 "1" → 01, 10~19 / 분 칸 "3" → 30, 35) 맞는 값이 없으면 목록이 숨겨지고 친 값 그대로 쓴다. 분은 직접 치면 1분 단위(예: 07)도 된다.
- [ ] AC-1d: 값이 들어 있는 칸(시 또는 분)을 다시 누르면 걸러지지 않은 목록 전체가 보이고, 지금 값이 강조된다. 새로 숫자를 치기 시작하면 AC-1c처럼 걸러진다. (값이 하나만 남아 다른 값으로 못 바꾸는 일이 없다)
- [ ] AC-2: 저장하면 `time: "HH:MM"`(24시간)으로 저장된다. 예: 시 "9", 분 "5" → "09:05" / 시 "14", 분 "07" → "14:07" / 시 "14", 분 비움 → "14:00" / 둘 다 비움 → `""`(종일). 저장 후 두 칸이 비워진다.
- [ ] AC-2a: 시가 24 이상, 분이 60 이상이거나, 분만 있고 시가 비어 있으면 저장되지 않고 입력 영역에 "시간을 확인해 주세요. (시 0~23, 분 0~59)"가 보인다. 올바르게 고쳐 저장하면 문구가 사라진다.
- [ ] AC-2b: 저장할 시간은 하나의 변환 함수(`combineTime`)를 거치므로 저장되는 `time`은 항상 "HH:MM" 또는 `""`이다.
- [ ] AC-3: 선택한 날짜의 일정 목록과 "다가오는 일정" 목록에서 시간이 있는 일정은 제목 앞에 "14:00"처럼 시간이 보이고, 시간이 없는 일정은 "종일"이 보인다.
- [ ] AC-4: 달력 날짜 칸에는 시간이 있는 일정이 "14:00 레슨"처럼 시간과 제목으로 보인다. 시간이 없으면 지금처럼 제목만 보인다.
- [ ] AC-5: 대시보드 "다가오는 D-DAY" 카드의 날짜 줄에 시간이 있으면 "10월 30일 (금) 14:00"처럼 함께 보인다.
- [ ] AC-6: 같은 날짜의 일정은 종일 일정이 먼저, 그다음 시간이 이른 순서로 보인다. 시간이 같으면 먼저 저장한 일정이 앞이다. 이 순서는 날짜 칸, 선택한 날짜 목록, 다가오는 일정, 대시보드 카드 모두 같다.
- [ ] AC-7: D-DAY 계산은 바뀌지 않는다. 시간과 관계없이 날짜 차이로만 "D-DAY / D-n / D+n"을 보여준다.
- [ ] AC-8: 시간 필드가 없는 기존 일정(F-002에서 저장한 데이터)은 앱을 열 때 `time: ""`(종일)로 읽히고, 목록에 "종일"로 보인다. 기존 일정이 사라지거나 앱이 멈추지 않는다.
- [ ] AC-9: 저장된 `time` 값이 "HH:MM" 형식이 아니면(예: "25시", 숫자) 종일 일정(`""`)으로 읽는다.
- [ ] AC-10: `src/lib/calendar.test.js`에 시간 관련 테스트가 추가된다 (time 없는 옛 데이터 마이그레이션, 잘못된 time 값, 같은 날 정렬 순서, 시·분 합치기 `combineTime`, 칸별 목록 거르기).
- [ ] AC-11: `npm test`, `npm run build`, `npm run lint`가 오류 없이 끝난다. (lint 경고는 기존 2건 외에 늘지 않는다)

## 비범위

- 끝나는 시간(시작~종료), 소요 시간
- 시간 단위 남은 시간 표시 (예: "3시간 남음"). D-DAY는 날짜 기준 유지
- 알림, 반복 일정, 일정 수정
- 오전/오후 12시간 표기 (24시간 "HH:MM"으로 통일)
- 선택 목록의 키보드 위/아래 화살표 이동 (마우스·터치로 고르고, 키보드는 직접 입력)

- 자동: `npm test`, `npm run build`, `npm run lint`
- 수동 (브라우저):
  1. `npm run dev` 실행 후 http://localhost:5173/ 열기
  2. (마이그레이션 확인) 업데이트 전에 시간 없이 저장해 둔 일정이 있다면 "종일"로 보이는지 본다. 없다면 먼저 시간을 비운 채 일정 "종일 테스트"를 저장한다.
  3. 시간 입력이 "[ 시 ] : [ 분 ]" 모양인지 본다. 시 칸을 눌러 "종일, 00~23" 목록이, 분 칸을 눌러 "00, 05 … 55" 목록이 열리는지 본다.
  3-1. 같은 날짜에 "레슨"은 목록에서 시 14 / 분 00을 골라 저장하고, "합주"는 시 10 / 분 07을 직접 쳐서 저장한다(시 2자리를 치면 분 칸으로 넘어가는지 본다) → 목록 순서가 "종일 테스트 → 10:07 합주 → 14:00 레슨"인지 본다.
  3-2. 시 칸에 25를 넣고 저장 → 저장되지 않고 안내 문구가 보이는지 본다.
  4. 날짜 칸에 "종일 테스트", "10:07 합주"와 "+1"이 보이는지 본다.
  5. "대시보드" 탭 카드에 날짜와 시간이 함께 보이는지 본다. (가장 가까운 일정이 종일이면 시간 없이 보인다)
  6. 새로고침 후에도 시간이 남아 있는지 본다.
  7. 테스트 일정을 삭제한다.
