# F-002: 캘린더와 D-DAY

- 상태: 구현됨
- 작성일: 2026-10-25
- 관련 파일: `src/App.jsx` (탭 목록 11–12줄, 상태·저장 24–50줄, 탭 화면 분기 230줄~), `src/App.css`, `src/lib/calendar.js` (새 파일), `src/lib/calendar.test.js` (새 파일)

## 목적

공연, 레슨, 오디션 같은 일정을 달력 날짜에 메모해 두고, 그 날까지 며칠 남았는지(D-DAY)를 한눈에 본다.

## 사용자 시나리오

1. 사용자가 왼쪽 메뉴에서 "캘린더"를 누른다.
2. 이번 달 달력이 보이고, 오늘 날짜가 강조되어 있다.
3. 날짜 칸을 누르면 그 날짜가 선택되고, 아래 입력칸에 일정 제목과 메모를 적어 저장한다.
4. 저장한 일정이 달력 날짜 칸에 표시되고, "다가오는 일정" 목록에 "D-5"처럼 남은 날이 보인다.
5. 대시보드 탭에서도 가장 가까운 일정의 D-DAY가 보인다.
6. 새로고침해도 일정이 남아 있고, 필요 없으면 삭제한다.

## 수용 기준

### 탭

- [ ] AC-1: 왼쪽 메뉴의 "연습 통계" 아래에 "캘린더" 탭이 보이고, 누르면 제목 "캘린더"가 있는 화면으로 바뀐다. 기존 탭 4개(대시보드 / 내 연습곡 / 연습 기록 / 연습 통계)는 이전과 똑같이 보인다.

### 달력

- [ ] AC-2: 처음 열면 오늘이 속한 달이 "2026년 10월" 형식의 제목과 함께 보이고, 요일 머리글은 "일 월 화 수 목 금 토" 순서다.
- [ ] AC-3: 날짜는 실제 요일 위치에 맞게 놓인다. (예: 2026년 10월 1일은 목요일 칸)
- [ ] AC-4: "‹"(이전 달), "›"(다음 달) 버튼으로 달을 옮길 수 있고, 12월에서 다음 달을 누르면 다음 해 1월로 바뀐다. "오늘" 버튼을 누르면 이번 달로 돌아온다.
- [ ] AC-5: 오늘 날짜 칸은 다른 칸과 구분되는 색으로 보인다(`.cal-day.today`).

### 일정 추가 / 표시 / 삭제

- [ ] AC-6: 날짜 칸을 누르면 그 칸이 선택 표시(`.cal-day.selected`)되고, 입력 영역에 "10월 30일 (금) 일정 추가"처럼 선택한 날짜가 보인다. 처음에는 오늘이 선택되어 있다.
- [ ] AC-7: 일정 제목(필수)과 메모(선택)를 입력하고 "일정 저장"을 누르면 그 날짜에 일정이 저장되고 입력칸이 비워진다. 제목이 비어 있으면 저장되지 않는다.
- [ ] AC-8: 일정이 있는 날짜 칸에는 일정 제목이 최대 2개까지 보이고, 3개 이상이면 "+n"이 함께 보인다.
- [ ] AC-9: 선택한 날짜의 일정 목록이 입력 영역 아래에 제목·메모·D-DAY와 함께 보이고, 각 일정의 "삭제" 버튼을 누르면 사라진다.

### D-DAY

- [ ] AC-10: D-DAY는 날짜(시간 무시) 차이로 계산한다. 일정이 오늘이면 "D-DAY", 미래면 "D-n", 지났으면 "D+n"으로 보인다. (예: 오늘이 10월 25일이면 10월 30일 일정은 "D-5", 10월 20일 일정은 "D+5")
- [ ] AC-11: "다가오는 일정" 목록에 오늘 포함 앞으로의 일정이 가까운 날짜 순으로 최대 5개 보인다. 지난 일정은 이 목록에 나오지 않는다. 앞으로의 일정이 없으면 "다가오는 일정이 없어요."가 보인다.

### 대시보드 D-DAY 카드

- [ ] AC-16: "대시보드" 탭의 곡 목록 위에 "다가오는 D-DAY" 카드가 보이고, 오늘 포함 가장 가까운 일정 1개의 제목, 날짜("10월 30일 (금)" 형식), D-DAY 표시("D-5" 등)가 보인다. 같은 날 일정이 여러 개면 먼저 저장한 일정이 보인다.
- [ ] AC-17: 앞으로의 일정이 없으면 카드에 "다가오는 일정이 없어요."가 보인다.
- [ ] AC-18: 카드의 "캘린더 열기" 버튼을 누르면 "캘린더" 탭으로 이동한다.
- [ ] AC-19: 이 카드는 "대시보드" 탭에만 보이고, "내 연습곡" 탭에는 보이지 않는다.

### 저장과 자동 검사

- [ ] AC-12: 일정은 localStorage `muselog-events`에 저장되어 새로고침 후에도 남아 있다.
- [ ] AC-13: `muselog-events`가 없거나 배열이 아닌 값(깨진 데이터)이어도 앱이 멈추지 않고 빈 캘린더로 열린다. 기존 키(`muselog-songs`, `muselog-minutes`, `muselog-goal`, `muselog-logs`)의 데이터는 그대로 유지된다.
- [ ] AC-14: 달력 칸 계산과 D-DAY 계산은 `src/lib/calendar.js`의 순수 함수로 분리되고, `src/lib/calendar.test.js`에 테스트가 있다 (월 시작 요일, 연도 넘김, D-DAY / D-n / D+n).
- [ ] AC-15: `npm test`, `npm run build`, `npm run lint`가 오류 없이 끝난다.

## 데이터 영향

| 항목 | 내용 |
|---|---|
| 사용하는 localStorage 키 | `muselog-events` (새 키, 읽기 / 쓰기) |
| 데이터 구조 변경 | 있음: 새 키 추가. `[{ id, date: "YYYY-MM-DD", title, memo }]`. 기존 키 구조는 바꾸지 않음 |
| 마이그레이션 | 옛 데이터가 없으므로 변환 불필요. 키가 없거나 배열이 아니면 빈 배열 `[]`로 시작하고, `date`/`title`이 없는 항목은 건너뛴다 |

`date`를 ISO 시각이 아닌 "YYYY-MM-DD" 문자열로 저장하는 이유: 일정은 "하루"에 붙는 것이라, 시간대 때문에 날짜가 하루 밀리는 문제를 피하기 위해서다.
