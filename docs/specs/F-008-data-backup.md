# F-008: 기록 백업 내보내기 / 불러오기

- 상태: 구현됨
- 작성일: 2026-10-30
- 관련 파일: `src/App.jsx` (상단 바 `topbar` 389줄 근처, localStorage 저장 effect 91–128줄), 새 파일 `src/lib/backup.js`, `src/lib/backup.test.js`, `src/App.css`, `CLAUDE.md` (폴더 구조)

## 목적

지금 기록은 브라우저 안(localStorage)에만 있어서, 브라우저 데이터를 지우거나 다른 주소·브라우저·기기에서 열면 보이지 않는다. 로그인 기능이 생기기 전까지, 모든 기록을 파일 하나로 내려받아 보관하고 필요할 때 그 파일로 되살릴 수 있게 한다. 다른 기기나 브라우저로 기록을 옮길 때도 쓸 수 있다.

## 사용자 시나리오

1. 사용자가 상단 바의 "백업 내보내기"를 누르면 `muselog-backup-2026-10-30.json` 파일이 내려받아진다.
2. 다른 브라우저(또는 다른 기기)에서 MUSELOG를 열고 "백업 불러오기"를 눌러 그 파일을 고른다.
3. "지금 이 브라우저의 기록이 백업 파일 내용으로 바뀝니다" 확인 창에서 확인을 누르면, 연습곡·연습 기록·일정·루틴·메트로놈 설정이 백업한 그대로 보인다.

## 수용 기준

### 내보내기

- [ ] AC-1: 상단 바 오른쪽(My Studio 옆)에 "백업 내보내기"와 "백업 불러오기" 버튼이 있고, 모든 탭에서 보인다.
- [ ] AC-2: "백업 내보내기"를 누르면 `muselog-backup-YYYY-MM-DD.json`(오늘 날짜) 파일이 내려받아진다.
- [ ] AC-3: 파일 내용은 `{ app: "muselog", version: 1, exportedAt: (ISO 시각), data: { ... } }` 형식의 JSON이다. `data`에는 CLAUDE.md 표의 9개 키(`muselog-songs`, `muselog-minutes`, `muselog-goal`, `muselog-logs`, `muselog-events`, `muselog-song-sort`, `muselog-metronome`, `muselog-routine`, `muselog-routine-checks`) 중 저장되어 있는 것이 키 이름 그대로, 저장된 값(JSON으로 읽은 값)으로 들어간다.

### 불러오기

- [ ] AC-4: "백업 불러오기"를 누르면 파일 고르기 창이 열리고 `.json` 파일을 고를 수 있다.
- [ ] AC-5: 올바른 백업 파일을 고르면 "지금 이 브라우저의 기록이 백업 파일 내용으로 바뀝니다. (백업 날짜: …) 계속할까요?" 확인 창이 뜬다. 취소하면 아무것도 바뀌지 않는다.
- [ ] AC-6: 확인하면 백업에 들어 있는 키는 백업 값으로 바뀌고, 백업에 없는 위 9개 키는 지워진다(백업한 시점 그대로 맞춤). 그 뒤 화면이 새로 고쳐져 백업 내용이 보인다. 위 9개 외의 키는 읽지도 쓰지도 않는다.
- [ ] AC-7: 불러온 값도 앱이 시작할 때 쓰는 읽기 함수(`normalizeSongs`, `normalizeMetronome`, `normalizeEvents`, `normalizeRoutine` 등)를 그대로 거치므로, 예전 형식의 백업도 지금 형식으로 읽힌다.
- [ ] AC-8: JSON이 아니거나, `app`이 `"muselog"`가 아니거나, `data`가 객체가 아닌 파일을 고르면 "MUSELOG 백업 파일이 아니에요." 안내가 보이고 기록은 바뀌지 않는다. 확인 창도 뜨지 않는다.
- [ ] AC-9: 백업 파일의 `version`이 1보다 크면(나중 버전에서 만든 파일) "더 새로운 버전의 백업 파일이라 불러올 수 없어요." 안내가 보이고 기록은 바뀌지 않는다.

### 공통

- [ ] AC-10: 백업 만들기와 읽기는 순수 함수 `buildBackup`(저장값 → 백업 객체)과 `parseBackup`(파일 글자 → `{ ok: true, backup }` 또는 `{ ok: false, error }`)으로 `src/lib/backup.js`에 두고 `src/lib/backup.test.js`에 테스트를 추가한다. (9개 키만 담기, 없는 키 빼기, 깨진 JSON, 다른 앱 파일, 새 버전 파일, 내보낸 것을 다시 읽으면 같은 내용)
- [ ] AC-11: 버튼을 누르지 않으면 기존 기능은 그대로다. 대시보드, 내 연습곡, 연습 기록, 연습 통계, 캘린더, 작업실이 이전과 똑같이 보이고 동작한다.
- [ ] AC-12: 좁은 화면(휴대폰 너비)에서도 상단 바 버튼이 화면 밖으로 넘치지 않는다.
- [ ] AC-13: `npm test`, `npm run build`, `npm run lint`가 오류 없이 끝난다. (lint 경고는 기존 개수보다 늘지 않는다)

## 비범위

- 로그인, 서버 저장, 기기 간 자동 동기화 (다음 기능에서)
- 자동 백업(정해진 때마다 저절로 내려받기)
- 백업과 지금 기록을 합치기 (불러오기는 통째로 바꾸기만)
- 항목별로 골라서 불러오기
- 백업 파일 암호화

## 데이터 영향

| 항목 | 내용 |
|---|---|
| 사용하는 localStorage 키 | 위 9개 키 (내보내기: 읽기만 / 불러오기: 사용자가 확인한 경우에만 쓰기·지우기) |
| 데이터 구조 변경 | 없음. 새 키도 만들지 않는다. 백업 파일은 브라우저 밖(내려받은 파일)에만 생긴다 |
| 마이그레이션 | 필요 없음. 예전 형식 백업도 기존 읽기 함수가 지금 형식으로 바꿔 읽는다(AC-7) |

## 확인 방법

- 자동: `npm test`, `npm run build`, `npm run lint`
- 수동 (브라우저):
  1. `npm run dev` 실행 후 http://localhost:5173/ 열기
  2. 곡·기록·루틴이 있는 상태에서 "백업 내보내기"를 눌러 파일이 내려받아지는지, 파일을 열어 9개 키가 들어 있는지 본다.
  3. 다른 브라우저(또는 같은 브라우저의 시크릿 창)에서 열고 "백업 불러오기"로 그 파일을 고른다. 확인 창에서 취소하면 그대로인지, 확인하면 기록이 똑같이 보이는지 본다.
  4. 아무 텍스트 파일이나 다른 JSON 파일을 골라 안내가 뜨고 기록이 그대로인지 본다.
  5. 휴대폰 너비에서 상단 바 버튼이 넘치지 않는지 본다.
