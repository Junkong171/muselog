# F-025: 마이크 안내 문구 고치기

- 상태: 구현됨
- 작성일: 2026-11-06
- 관련 파일: 새 파일 `src/lib/mic.js`, `src/lib/mic.test.js`, `src/Tuner.jsx`, `src/voiceMemo.js`, `CLAUDE.md`

## 목적

마이크가 막혔을 때 지금은 "주소창 왼쪽 자물쇠에서 허용"이라고 안내한다. 그런데 홈 화면에 설치한 앱에는 주소창이 없어서 따라 할 수 없다. (실제로 삼성 인터넷으로 설치한 앱에서 막혔다.) 설치한 앱에서는 브라우저 앱 설정 경로를 안내하고, 튜너와 음성 메모가 같은 문구를 쓰게 한다.

## 사용자 시나리오

1. 홈 화면에 설치한 MUSELOG에서 녹음(또는 튜너)을 누른다. 마이크가 막혀 있다.
2. "이 앱을 설치한 브라우저(삼성 인터넷·Chrome 등)의 설정 → 사이트 권한 → 마이크에서 허용"하라는 안내가 보인다.
3. 브라우저 탭에서 연 경우에는 지금처럼 주소창 자물쇠 안내가 보인다.

## 수용 기준

- [ ] AC-1: 마이크 권한이 막혔을 때(`NotAllowedError`, `SecurityError`) 설치한 앱으로 열었으면 다음 안내가 보인다: "마이크 사용이 허락되지 않았어요. 이 앱을 설치한 브라우저(삼성 인터넷·Chrome 등)의 설정 → 사이트 권한 → 마이크에서 허용하고, 앱을 다시 열어 주세요. 휴대폰 설정에서 그 브라우저의 마이크 권한도 확인해 주세요."
- [ ] AC-2: 브라우저 탭에서 열었으면 지금 문구 "마이크 사용이 허락되지 않았어요. 주소창 왼쪽 자물쇠에서 마이크를 허용해 주세요."가 그대로 보인다.
- [ ] AC-3: "마이크를 찾지 못했어요…", "마이크를 켜지 못했어요…" 문구는 지금과 같다.
- [ ] AC-4: 튜너(작업실 탭)와 음성 메모(영감 탭)가 같은 함수(`src/lib/mic.js`의 `micErrorMessage`)로 문구를 만든다. 두 파일에 따로 있던 같은 함수는 없어진다.
- [ ] AC-5: "설치한 앱으로 열었는지"는 화면 표시 방식이 `standalone`인지(`display-mode: standalone`, 아이폰은 `navigator.standalone`)로 판단한다.
- [ ] AC-6: `micErrorMessage`의 경우별 문구를 자동 테스트로 확인한다 (권한 막힘 × 앱/브라우저, 마이크 없음, 그 밖의 오류).
- [ ] AC-7: `npm test`, `npm run build`, `npm run lint`가 오류 없이 끝난다.

## 비범위

- 앱이 마이크 허용 창을 다시 띄우게 하기 (브라우저 보안 규칙상 불가능)
- 브라우저 종류(삼성 인터넷/Chrome/Safari)를 알아내서 브라우저마다 다른 경로 안내하기
- 마이크 권한 상태를 미리 확인해 버튼을 바꾸기

## 확인 방법

- 자동: `npm test`, `npm run build`, `npm run lint`
- 수동 (브라우저):
  1. `npm run dev` 실행 후 http://localhost:5173/ 열기
  2. 주소창 자물쇠에서 마이크를 차단하고 영감 탭 **녹음**, 작업실 탭 튜너 켜기 → 자물쇠 안내 확인
  3. 배포 후 설치한 앱에서 마이크를 차단하고 같은 동작 → 브라우저 설정 안내 확인
