# F-016: 캘린더 연습 기간 메모

- 상태: 구현됨
- 작성일: 2026-11-01
- 관련 파일: `src/lib/periods.js`(새로), `src/lib/periods.test.js`(새로), `src/lib/backup.js`, `src/lib/sync.js`, `src/lib/sync.test.js`, `src/App.jsx`, `src/App.css`, `public/privacy.html`, `CLAUDE.md`

## 목적

백업 기능이 생기기 전의 연습 기록은 남아 있지 않지만, "언제부터 언제까지 무엇을 중점으로 연습했는지"는 기억난다. 이를 캘린더에 **기간 단위**로 적어 두고, 앞으로도 "이번 달은 ○○ 집중"처럼 연습 흐름을 남길 수 있게 한다.

## 사용자 시나리오

1. 캘린더 탭에서 "연습 기간 메모" 카드에 시작일·끝일, 중점 연습(예: 기타 코드 전환), 메모를 적고 저장한다.
2. 달력에서 그 기간에 들어가는 날짜 칸마다 색 띠가 보이고, 기간이 시작하는 날(또는 그 달의 1일)에는 제목이 보인다.
3. 날짜를 누르면 그날이 들어가는 연습 기간이 일정 목록 위에 보인다.
4. 카드 아래 목록에서 기간을 수정하거나 삭제한다.

## 수용 기준

- [ ] AC-1: 캘린더 탭에 "연습 기간 메모" 카드가 있고, 시작일·끝일(날짜 선택 칸), 중점 연습(1~40자, 필수), 메모(0~200자, 선택) 칸과 "기간 저장" 버튼이 있다. 시작일·끝일의 처음 값은 달력에서 고른 날짜다.
- [ ] AC-2: 중점 연습이 비어 있거나 날짜가 비어 있으면 저장되지 않고 안내 문구가 보인다. 끝일이 시작일보다 앞이면 두 날짜를 바꿔서 저장한다.
- [ ] AC-3: 저장한 기간에 속한 날짜 칸에 색 띠가 보인다. 기간의 시작일 칸(시작일이 이전 달이면 그 달 1일 칸)에는 띠 안에 중점 연습 제목이 보인다. 한 날짜에 기간이 여러 개 겹치면 띠는 최대 2개까지 보이고, 기존 일정 표시(최대 2개, +N)는 그대로 보인다.
- [ ] AC-4: 날짜를 누르면 그날을 포함하는 연습 기간이 "이 날의 연습 기간"으로 일정 목록 위에 보인다(제목, `2026.3.1 ~ 2026.5.31 · 92일`, 메모).
- [ ] AC-5: 카드 아래 목록에 모든 기간이 시작일이 늦은 순으로 보이고, 각 줄에 "수정"과 "삭제" 버튼이 있다. "수정"을 누르면 위 입력 칸에 값이 채워지고 버튼이 "수정 저장"/"취소"로 바뀐다. "삭제"는 확인 창을 띄운 뒤 지운다.
- [ ] AC-6: 기간은 localStorage 키 `muselog-periods`에 `[{ id, start("YYYY-MM-DD"), end("YYYY-MM-DD"), title, memo }]`로 저장되어 새로고침 뒤에도 남는다. 깨진 값(배열 아님, 날짜 형식 틀림, 제목 없음)은 버리고, start > end인 항목은 바꿔서 읽는다. 키가 없으면 빈 목록.
- [ ] AC-7: `muselog-periods`가 `BACKUP_KEYS`에 들어 있어 백업 내보내기/불러오기와 계정 동기화(자동 저장 effect의 감시 목록 포함)에 함께 담긴다. 연습 기간 메모만 있는 브라우저도 "기록 있음"으로 쳐서, 처음 로그인할 때 묻지 않고 덮어쓰지 않는다(`isEmptyData`).
- [ ] AC-8: 기존 일정 추가·삭제, 다가오는 일정, 대시보드 D-DAY 카드가 이전과 똑같이 동작한다.
- [ ] AC-9: 화면 폭 700px 이하에서 카드와 달력 띠가 화면 밖으로 넘치지 않는다.
- [ ] AC-10: 개인정보처리방침의 계정에 저장하는 기록 목록에 "연습 기간 메모"가 들어간다.
- [ ] AC-11: `src/lib/periods.test.js`가 정규화·정렬·날짜 포함 판정·일수 계산을 검사하고, `npm test`, `npm run build`, `npm run lint`가 오류 없이 끝난다.

## 비범위

- 기간 메모를 연습 통계(분 합계)에 반영하기: 기간 메모는 시간 기록이 아니라 기억 메모다
- 기간 색 고르기(한 가지 색만)
- 대시보드에 "지금 진행 중인 연습 기간" 보여 주기
- 달력 칸을 끌어서 기간 고르기

## 데이터 영향

| 항목 | 내용 |
|---|---|
| 사용하는 localStorage 키 | `muselog-periods` (새로, 읽기/쓰기). 다른 키는 그대로 |
| 데이터 구조 변경 | 새 키 추가만. 기존 키 구조는 바뀌지 않음 |
| 마이그레이션 | 필요 없음. 키가 없는 기존 사용자는 빈 목록으로 시작. 이 키가 없는 옛 백업 파일을 불러와도 그대로 동작 |

## 확인 방법

- 자동: `npm test`, `npm run build`, `npm run lint`
- 수동 (브라우저):
  1. `npm run dev` 실행 후 http://localhost:5173/ → 캘린더 탭
  2. 지난달 10일 ~ 이번 달 5일, "기타 코드 전환" 저장 → 두 달 모두 띠와 제목 확인
  3. 날짜 눌러 "이 날의 연습 기간" 확인, 수정·삭제
  4. 새로고침 뒤에도 남는지, 백업 내보내기 파일에 `muselog-periods`가 있는지
  5. 휴대폰 폭에서 확인
