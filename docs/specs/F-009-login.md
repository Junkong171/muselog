# F-009: 로그인 1단계 (구글·카카오)

- 상태: 구현됨
- 작성일: 2026-10-30
- 관련 파일: `src/App.jsx` (상단 바 `topbar`의 `profile` 영역), 새 파일 `src/lib/supabase.js`, `src/lib/auth.js`, `src/lib/auth.test.js`, `src/App.css`, `package.json` (새 라이브러리 `@supabase/supabase-js`), `.env.example` (새 파일, 키 이름만), `CLAUDE.md` (폴더 구조, 실행·설정 안내)
- 다음 단계: F-010 (로그인한 계정에 기록 저장·불러오기)

## 목적

기록을 계정에 저장해 어느 기기에서나 같은 기록을 보려면 먼저 "누구인지" 알아야 한다. 이번 단계는 구글·카카오 계정으로 로그인·로그아웃만 할 수 있게 하고, 기록 저장 방식은 바꾸지 않는다. 로그인은 선택이라, 로그인하지 않아도 지금처럼 모든 기능을 쓸 수 있다.

로그인과 계정 관리는 Supabase(로그인·데이터 보관을 대신해 주는 서비스)에 맡긴다. 직접 서버를 만들지 않는다.

## 사용자 시나리오

1. 사용자가 상단 바의 "로그인"을 누르면 "구글로 로그인", "카카오로 로그인" 버튼이 있는 작은 창이 열린다.
2. "카카오로 로그인"을 누르면 카카오 로그인 화면으로 갔다가, 로그인이 끝나면 MUSELOG로 돌아온다.
3. 상단 바에 "M My Studio" 대신 사용자 이름(예: "준서")과 "로그아웃" 버튼이 보인다. 기록은 로그인 전과 똑같이 보인다.
4. 새로고침하거나 다음 날 다시 열어도 로그인이 유지된다.
5. "로그아웃"을 누르면 다시 "M My Studio"와 "로그인" 버튼으로 돌아간다. 기록은 그대로다.

## 수용 기준

### 로그인 전

- [ ] AC-1: 로그인하지 않은 상태에서 상단 바에 지금처럼 "M My Studio"가 보이고, 그 옆에 "로그인" 버튼이 있다. 모든 탭에서 보인다.
- [ ] AC-2: "로그인"을 누르면 상단 바 아래에 작은 창이 열리고 "구글로 로그인", "카카오로 로그인" 두 버튼과 "로그인하면 다음 업데이트부터 기록을 계정에 저장할 수 있어요. 로그인하지 않아도 지금처럼 쓸 수 있어요." 같은 안내가 보인다. 창 바깥을 누르거나 Esc를 누르거나 "닫기"를 누르면 닫힌다.
- [ ] AC-3: 로그인하지 않아도 6개 탭의 모든 기능(기록, 곡, 일정, 루틴, 메트로놈, 백업)이 지금과 똑같이 동작한다.

### 로그인

- [ ] AC-4: "구글로 로그인" / "카카오로 로그인"을 누르면 그 회사의 로그인 화면으로 이동한다(Supabase OAuth). 로그인을 마치면 같은 MUSELOG 주소(개발용이면 localhost, 배포 사이트면 배포 주소)로 돌아온다.
- [ ] AC-5: 로그인되면 상단 바의 "M My Studio" 자리에 이름 첫 글자 동그라미와 사용자 이름이 보이고, 그 옆에 "로그아웃" 버튼이 보인다. "로그인" 버튼은 보이지 않는다.
- [ ] AC-6: 보이는 이름은 계정 정보의 이름(구글 이름 또는 카카오 닉네임)이고, 없으면 이메일의 @ 앞부분, 그것도 없으면 "사용자"다. 이 규칙은 순수 함수 `displayName(user)`(`src/lib/auth.js`)로 한다.
- [ ] AC-7: 로그인한 상태에서 새로고침하거나 브라우저를 닫았다 열어도 로그인이 유지된다. (Supabase가 로그인 정보를 브라우저에 보관)
- [ ] AC-8: 로그인 중 사용자가 취소했거나 오류가 나서 돌아오면 "로그인하지 못했어요. 다시 시도해 주세요." 안내가 보이고, 로그인 전 상태로 남는다. 주소창에 남은 오류 글자는 지운다.

### 로그아웃

- [ ] AC-9: "로그아웃"을 누르면 로그인 전 상태(AC-1)로 돌아간다. 이 브라우저의 기록(9개 키)은 지우지 않는다.

### 설정이 없을 때

- [ ] AC-10: Supabase 키(`VITE_SUPABASE_URL`, `VITE_SUPABASE_ANON_KEY`)가 설정되지 않았으면 앱은 오류 없이 지금처럼 동작하고, "로그인" 버튼 대신 아무것도 보이지 않는다(또는 눌러도 "로그인 준비 중이에요." 안내만 보인다). `npm test`, `npm run build`도 키 없이 성공한다.
- [ ] AC-11: 키는 `.env.local` 파일(git에 올라가지 않음)과 Vercel 설정에만 넣는다. 저장소에는 키 이름만 적힌 `.env.example`을 둔다. 키 값을 코드에 직접 쓰지 않는다.

### 공통

- [ ] AC-12: `displayName`과 키 설정 여부 판단 `isAuthConfigured(env)`를 `src/lib/auth.js`에 두고 `src/lib/auth.test.js`에 테스트를 추가한다.
- [ ] AC-13: 좁은 화면(휴대폰 너비)에서도 상단 바와 로그인 창이 화면 밖으로 넘치지 않는다.
- [ ] AC-14: 대시보드, 내 연습곡, 연습 기록, 연습 통계, 캘린더, 작업실, 백업 버튼이 로그인 전후 모두 이전과 똑같이 동작한다.
- [ ] AC-15: `npm test`, `npm run build`, `npm run lint`가 오류 없이 끝난다. (lint 경고는 기존 개수보다 늘지 않는다)

## 비범위

- 기록을 계정(서버)에 저장하거나 다른 기기에서 불러오기 → F-010
- 네이버 로그인 (Supabase 기본 지원이 없어 따로 작업)
- 이메일·비밀번호 회원가입, 회원 탈퇴, 프로필 사진 표시
- 로그인해야만 쓸 수 있는 기능

## 데이터 영향

| 항목 | 내용 |
|---|---|
| 사용하는 localStorage 키 | MUSELOG 9개 키는 읽지도 쓰지도 않는다. Supabase 라이브러리가 로그인 정보를 자기 키(`sb-…-auth-token`)에 따로 저장한다 |
| 데이터 구조 변경 | 없음. 백업(`BACKUP_KEYS`)에도 로그인 정보는 넣지 않는다 |
| 마이그레이션 | 필요 없음 |
| 외부 서비스 | Supabase에 로그인한 사람의 계정 정보(이름, 이메일, 로그인 방식)가 저장된다. 연습 기록은 이번 단계에서 보내지 않는다 |

## 사용자가 직접 할 일 (구현 전후로 단계별 안내)

1. Supabase 가입, 프로젝트 만들기 → Project URL과 anon key 확인
2. Google Cloud 콘솔에서 OAuth 클라이언트 만들기 → Supabase의 Google 설정에 입력
3. 카카오 디벨로퍼스에서 앱 등록, 카카오 로그인 켜기, Redirect URI 등록 → Supabase의 Kakao 설정에 입력
4. Supabase의 허용 주소(Redirect URLs)에 `http://localhost:5173`과 `https://muselog-swart.vercel.app` 등록
5. `.env.local`에 키 넣기 (`.env` 계열 파일이라 승인 후 진행), Vercel 프로젝트 설정의 환경 변수에도 같은 키 넣기

## 확인 방법

- 자동: `npm test`, `npm run build`, `npm run lint` (키 없이)
- 수동 (브라우저):
  1. 키 없이 `npm run dev` → 앱이 지금처럼 동작하고 오류가 없는지 본다.
  2. `.env.local`에 키를 넣고 다시 `npm run dev` → "로그인" 버튼과 창을 본다.
  3. 구글로 로그인 → 돌아와서 이름과 "로그아웃"이 보이는지, 새로고침해도 유지되는지 본다. 로그아웃해 본다.
  4. 카카오로도 같은 확인을 한다. 카카오 화면에서 취소하고 돌아와 안내가 뜨는지 본다.
  5. 로그인 전후 기록과 다른 탭이 그대로인지 본다.
  6. (배포 후) 배포 사이트에서도 로그인이 되는지 본다.
