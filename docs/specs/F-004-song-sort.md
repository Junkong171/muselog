# F-004: 연습곡 목록 정렬

- 상태: 구현됨 (수정 1차: 정렬 기준 기억하기)
- 작성일: 2026-10-26
- 관련 파일: `src/App.jsx` (연습곡 목록 제목 영역 670–680줄, 목록 화면 698–732줄), 새 파일 `src/lib/songs.js`, `src/lib/songs.test.js`, `src/App.css`

## 목적

연습곡이 많아지면 원하는 곡을 찾기 어렵다. 목록을 제목순이나 진행률순으로 바꿔 보면 곡을 빨리 찾고, 거의 완성된 곡이나 아직 덜 된 곡을 한눈에 볼 수 있다.

## 사용자 시나리오

1. 사용자가 "내 연습곡" 탭에서 목록 위의 정렬 선택에서 "진행률순"을 고른다.
2. 진행률이 높은 곡부터 차례로 보인다.
3. "제목순"을 고르면 가나다순으로 보이고, "추가한 순"을 고르면 원래 순서로 돌아온다.

## 수용 기준

- [ ] AC-1: 연습곡 목록 바로 위에 정렬 선택이 보이고, 고를 수 있는 값은 "추가한 순", "제목순", "진행률순" 3가지다. 저장된 기준이 없으면(처음 쓰는 경우) "추가한 순"이다.
- [ ] AC-2: "추가한 순"은 지금과 같은 순서(곡을 추가한 순서)로 보인다.
- [ ] AC-3: "제목순"은 제목 가나다순(한글 ㄱ→ㅎ, 영어 A→Z, 대소문자 구분 없음)으로 보인다. 제목이 같으면 추가한 순서를 따른다.
- [ ] AC-4: "진행률순"은 진행률이 높은 곡부터 보인다. (예: 75% → 45% → 30%) 진행률이 같으면 제목순을 따른다.
- [ ] AC-5: 정렬은 보이는 순서만 바꾼다. 저장된 연습곡 데이터(`muselog-songs`)의 순서와 내용은 바뀌지 않아서, "추가한 순"으로 돌아오면 원래 순서가 그대로다.
- [ ] AC-6: 정렬된 상태에서 곡을 추가하거나 "진도 +10%"를 누르면, 고른 정렬 기준에 맞게 바로 다시 정렬된다. "진도 +10%"는 누른 곡에만 적용된다.
- [ ] AC-7: 각 곡의 표지 그림(♫ ♪ ♬ ♩와 색)은 정렬 기준을 바꿔도 그 곡의 것이 그대로 유지된다.
- [ ] AC-8: 연습곡이 0곡이면 정렬 선택 없이 지금처럼 "첫 번째 연습곡을 추가해 보세요." 안내만 보인다.
- [ ] AC-9: 정렬 계산은 순수 함수 `sortSongs(songs, sortKey)`(`src/lib/songs.js`)로 분리하고, `src/lib/songs.test.js`에 테스트를 추가한다. (세 기준, 같은 값일 때 순서, 원본 배열을 바꾸지 않음, 모르는 기준은 추가한 순)
- [ ] AC-9a: 고른 정렬 기준은 새 localStorage 키 `muselog-song-sort`에 저장되어, 새로고침하거나 다른 탭에 갔다 와도 그대로 유지된다.
- [ ] AC-9b: `muselog-song-sort` 값이 없거나 "added", "title", "progress"가 아니면(깨진 값) "추가한 순"으로 읽고 앱은 멈추지 않는다. 이 처리는 `normalizeSongSort` 함수(`src/lib/songs.js`)로 하고 테스트를 추가한다.
- [ ] AC-10: `npm test`, `npm run build`, `npm run lint`가 오류 없이 끝난다. (lint 경고는 기존 2건 외에 늘지 않는다)

## 확인 방법

- 자동: `npm test`, `npm run build`, `npm run lint`
- 수동 (브라우저):
  1. `npm run dev` 실행 후 http://localhost:5173/ 열기
  2. "내 연습곡" 탭에서 목록 위에 정렬 선택이 "추가한 순"으로 보이는지 본다.
  3. "제목순"을 골라 가나다순인지, "진행률순"을 골라 높은 순인지 본다. 표지 그림이 곡을 따라가는지 본다.
  4. "진행률순"에서 아래쪽 곡의 "진도 +10%"를 몇 번 눌러 위로 올라가는지 본다.
  5. "추가한 순"으로 돌아와 원래 순서인지 본다. "진행률순"을 고른 채 새로고침해서 "진행률순"이 유지되는지 본다.
  6. 대시보드, 연습 기록, 연습 통계, 캘린더 탭이 그대로인지 본다.
