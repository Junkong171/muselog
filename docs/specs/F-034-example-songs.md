# F-034: 처음 화면 예시 곡 줄이기

- 상태: 구현됨
- 작성일: 2026-11-11
- 관련 파일: `src/lib/songs.js`(예시 곡 목록), `src/lib/sync.js`(비어 있음 판단), 테스트 `src/lib/songs.test.js`·`src/lib/sync.test.js`

## 목적

처음 여는 사람(저장된 기록이 없는 브라우저, 로그인하지 않은 상태)에게 깔리는 예시 연습곡을 "밤편지"와 "너를 생각해" 두 곡으로 줄인다.

## 사용자 시나리오

1. 기록이 하나도 없는 브라우저(예: 새 시크릿 창)에서 앱을 연다.
2. "내 연습곡" 탭과 대시보드에 예시 곡으로 "밤편지"(아이유, 보컬)와 "너를 생각해"(주시크, 기타) 두 곡만 보인다.

## 수용 기준

- [ ] AC-1: 저장된 `muselog-songs`가 없는 브라우저에서 앱을 열면 연습곡이 "밤편지", "너를 생각해" 두 곡만 보인다. "사랑은 늘 도망가"는 보이지 않는다.
- [ ] AC-2: 이미 연습곡이 저장된 사용자(예전 예시 곡 3개를 그대로 둔 사용자 포함)의 목록은 바뀌지 않는다. 앱이 저장된 곡을 지우지 않는다.
- [ ] AC-3: 계정 동기화의 "비어 있음" 판단(`isEmptyData`)은 새 예시 곡 2개 그대로인 기기와 예전 예시 곡 3개 그대로인 기기를 모두 "비어 있음"으로 본다. (첫 로그인 때 예시 곡만 있는 기기는 묻지 않고 계정 기록을 불러온다)
- [ ] AC-4: 예시 곡 2개에 곡을 하나 더하거나, 예시 곡의 제목을 바꾸면 "비어 있음"이 아니다.
- [ ] AC-5: `npm test`, `npm run build`, `npm run lint`가 오류 없이 끝난다.

## 비범위

- 이미 저장된 사용자 데이터에서 "사랑은 늘 도망가"를 지우기 (사용자 기록은 건드리지 않는다)
- 로그아웃할 때 기록을 지우는 동작 (지금처럼 로그아웃해도 이 브라우저의 기록은 남는다)
- 예시 곡의 진행률·파트 변경

## 데이터 영향

| 항목 | 내용 |
|---|---|
| 사용하는 localStorage 키 | `muselog-songs` (저장값이 없을 때의 기본값만 바뀜) |
| 데이터 구조 변경 | 없음 |
| 마이그레이션 | 필요 없음. 저장된 곡 목록은 그대로 읽는다. 동기화의 "비어 있음" 판단은 예전 예시 곡 3개도 계속 인정한다 |

## 확인 방법

- 자동: `npm test`, `npm run build`, `npm run lint`
- 수동 (브라우저):
  1. `npm run dev` 실행 후 http://localhost:5173/ 을 기록이 없는 창(시크릿 창)에서 열기
  2. "내 연습곡" 탭에 "밤편지", "너를 생각해" 두 곡만 있는지 확인
